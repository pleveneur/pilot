# Pilot v0.4.36

Cette version s'attaque aux demandes qui disparaissaient et aux lancements qui
doublonnaient : arrêter un agent ne détruit plus les missions en attente, une
demande déposée respecte l'ordre d'arrivée même quand le projet paraît libre, et
un projet n'a plus qu'une seule identité quelle que soit l'écriture de son
chemin. L'aide annonce par ailleurs le vrai délai d'inactivité, et un contrôle
empêche la documentation de repartir en arrière.

Elle regroupe tout le travail fait depuis la version que vous avez installée
(0.4.35) : rien n'en a été publié entre-temps.

## 🐛 Corrections

- **Arrêter un agent ne détruit plus les missions en attente.** Les demandes qui
  patientaient derrière cet agent sont désormais **conservées** au lieu d'être
  jetées avec l'arrêt : chacune garde son **numéro de mission** et la liste des
  agents qu'elle vise, une même demande ne peut plus être empilée deux fois, et
  le journal indique lesquelles ont été reprises. Elles **rejouent** d'elles-mêmes
  dès que l'agent est de nouveau disponible.
- **Une demande respecte désormais l'ordre d'arrivée.** Une demande déposée
  pendant qu'un agent termine son tour passe maintenant à la file au lieu de
  démarrer en parallèle : le projet n'est plus considéré comme libre simplement
  parce qu'aucune exécution n'est visible à cet instant. Deux demandes lancées à
  quelques secondes d'intervalle partent donc dans l'ordre où vous les avez
  écrites.
- **Un projet est identifié de façon unique, quelle que soit l'écriture de son
  chemin.** Le même dossier désigné avec des barres obliques ou inverses, une
  majuscule ou une barre finale n'ouvre plus deux files concurrentes : la même
  file et le même verrou s'appliquent partout, ce qui supprime les lancements
  simultanés sur un projet pourtant déjà occupé.

## ⚡ Améliorations

- **Le délai d'inactivité annoncé est enfin le vrai.** L'aide annonçait
  5 minutes alors que la valeur appliquée est de **10 minutes par défaut**
  (600 000 ms), réglable dans les Paramètres. Un test de vérification empêche
  maintenant la documentation de diverger à nouveau : si la valeur change sans
  que l'aide suive, la vérification échoue et la version ne peut plus être
  publiée.
- **Documentation et aide intégrées remises d'accord avec le comportement réel**
  sur l'arrêt d'un agent, l'ordre d'arrivée et l'identité de projet.

## ℹ️ Limites connues

Deux limites subsistent. Elles sont écrites ici pour être connues, pas pour être
cachées : aucune ne perd ni ne duplique une demande, et aucune ne masque un
échec.

- **L'ordre d'attente peut changer, jamais la demande.** Une mission déjà sortie
  de file qui ne trouve pas le projet libre est remise en file **derrière** les
  suivantes : avec deux demandes B puis C en attente, l'ordre peut devenir C
  puis B. Même mission, même numéro, rejeu réarmé — rien n'est perdu, rien n'est
  dupliqué, l'attente supplémentaire est d'au plus un tour de rejeu (15 s).
- **La file des commandes manuelles reste rangée par le chemin tel qu'écrit.** Si
  le même dossier est désigné avec deux écritures différentes, deux files de
  commandes manuelles coexistent et l'affichage de la file peut ne pas voir les
  commandes posées sous l'autre écriture. Chaque commande démarre quand même à
  son tour, rien n'est perdu. Les autres files (missions, délégations,
  exclusivité) sont, elles, bien unifiées.
